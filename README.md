# Financial-Agent-Copilot

은행 상담직원용 업무보조 AI 에이전트 — 상품추천·환율조회·사내규정질의를 자연어로 처리하는 CLI 기반 Agent.

## 핵심 요약

- **Agent 설계·구현** — LangGraph StateGraph를 기반으로 사용자 query에 대해 routing → (RAG / tool call) → 가드레일 → answer로 이어지는 분기형 파이프라인 구현
- **의도·대화상태 라우팅** — 4클래스 분류 + 대화이력 반영 + 저신뢰 시 재작성 복구(Tier0)
- **컨텍스트 조합** — 대화이력 재사용(멀티턴) + RAG 검색결과 + tool 호출 결과(API 응답)를 결합해 답변 생성
- **Tool/API 예외처리** — 실API 6개 연동. Tier1(라우팅·tool선택은 맞다고 전제, 외부 API 자체 문제 — fail/delay)·Tier2(API는 정상인데 Agent의 해석이 잘못됐을 가능성 — 결과없음/파라미터무효/tool미선택) 두 계층으로 나눠 재시도·복구
- **가드레일** — 5규칙 자동교정(PII마스킹/필수고지/금지표현/숫자검증/citation grounding)
- **테스트셋 기반 품질개선** — 복합 시나리오 64건 Agent 정확도 평가, 87.5%(train) / 93.8%(test) (tool 재사용 프롬프트 버그 수정)

## Agent 구조도

```
                     query
                       │
                  router ← Tier0
       ┌───────────────┼───────────────┐
상품추천/환율조회   사내규정질의(RAG)   out_of_scope
       │                   │              │
  ┌─→ tool call ← Tier1/2  │              │
  │      │  │              │              │
  └──────┘  └─────┬────────┘              │
                  │                       │
              guardrail                   │
                  │                       │
                answer ───────────────────┘

Tier0 — 라우팅 실패 시 노드 내부에서 1회 재작성 후 재분류
Tier1/2 — API레벨 예외처리(tool call 그래프 self-loop 재시도)
```

라우터가 발화를 4클래스(상품추천/환율조회/사내규정질의/범위외)로 분류하면, route별로 필요한 노드로만 바로 분기합니다(LangGraph의 conditional edge 패턴) — 해당 없는 노드는 아예 호출되지 않습니다. 자세한 내용은 [src/graph/README.md](src/graph/README.md)를 참고해 주세요.

## 주요 기능

### 상품추천

정기예금·신용대출·전세자금대출·주택담보대출·개인사업자대출 5종, 금융감독원 「금융상품한눈에」 실API 기반.

```
질문: 정기예금 상품 추천해줘
답변: 현재 가입 가능한 정기예금 상품 중에서 추천드릴 만한 상품은 다음과 같습니다. 
1. **한국스탠다드차타드은행 - e-그린세이브예금** - 가입 기간: 12개월 - 기본 금리: 연 3.65% - 우대 금리 적용 시: 연 3.85% 
2. **전북은행 - JB 123 정기예금 (만기일시지급식)** - 가입 기간: 12개월 - 기본 금리: 연 3.21% - 우대 금리 적용 시: 연 3.81% 
3. **농협은행주식회사 - NH왈츠회전예금 II** - 가입 기간: 12개월 - 기본 금리: 연 3.15% - 우대 금리 적용 시: 연 3.25% 
이 중에서 가장 높은 금리를 제공하는 상품은 한국스탠다드차타드은행의 e-그린세이브예금입니다. 
※ 실제 가입 조건과 금리는 상품설명서·약관 확인 후 최종 확정됩니다. 자세한 사항은 영업점 또는 고객센터에 문의하세요.
```

### 환율조회

원/달러 환율, 한국은행 ECOS 실API 기반.

```
질문: 환율 알려줘
답변: 현재 USD/KRW 환율은 1397.7원입니다. (기준일: 2026.08.19)
```

### 사내규정질의

개인정보보호·전자금융·금융상품 설명의무·마이데이터·예금거래약관 등 13개 문서 기반 RAG 검색.

```
질문: 예금거래기본약관은 은행 영업점에서 언제 볼 수 있나요?
답변: 문서에 따르면, 예금거래기본약관을 은행 영업점에서 열람할 수 있는 시간에 대해 다음과 같이 규정하고 있습니다:

"은행은 이 약관을 영업점에 놓아두고, 거래처는 영업시간 중 언제든지 이 약관을 볼 수 있고 또한 그 교부를 청구할 수 있다."

따라서, 예금거래기본약관은 은행 영업점의 영업시간 중에 열람할 수 있습니다.
```

### 대화이력 반영(멀티턴)

이전 턴에서 확정된 조건을 후속 발화에도 재사용합니다.

```
질문(1턴): 정기예금 좋은 상품 추천해줘
답변(1턴): 12개월 기준 정기예금 상품 3건을 안내드립니다.

질문(2턴): 6개월짜리로 다시 봐줘
답변(2턴): 6개월짜리 예금 상품의 금리는 다음과 같습니다.

- 전북은행의 'JB 다이렉트예금통장(만기일시지급식)'은 기본금리와 우대금리 모두 연 3.45%입니다.
- 한국스탠다드차타드은행의 'e-그린세이브예금'은 기본금리 3.2%, 우대금리 3.4%입니다.
- 농협은행의 'NH왈츠회전예금 II'는 기본금리 2.95%, 우대금리 3.05%입니다.

이렇게 세 가지 상품이 있습니다.
```

"12개월"이라는 조건 언급 없이 "6개월짜리로 다시 봐줘"라고만 말해도, 이전 턴에서 조회한 상품군(정기예금)이 뭐였는지를 기억해 기간 조건만 바꿔 재조회합니다.

## 가드레일

답변을 내보내기 전 5규칙을 자동교정으로 통과시킵니다(사람 개입 없음).

| 규칙 | 내용 | 메커니즘 |
| --- | --- | --- |
| ① PII 마스킹 | 주민번호/카드번호/계좌번호 | 정규식, 숫자 앞 두자리만 남기고 마스킹 |
| ② 필수고지 자동삽입 | 상품 설명 시 법정 고지문구 누락 방지 | 규칙기반 |
| ③ 금지표현 차단 | "원금보장"/"확정수익" 등 과장·단정 표현 | 사전 매칭 + LLM semantic 탐지 |
| ④ 숫자 자체검증 | 답변 속 숫자를 원본 API값과 대조 | route별 정규식 또는 LLM 추출 |
| ⑤ citation grounding | RAG 인용 주장이 검색문서로 실제 뒷받침되는지 | LLM entailment 판정 |

위반이 발견되면 해당 문구가 포함된 문장을 통째로 제거합니다(단어만 지우면 문법이 깨지는 문제를 방지). 규칙 하나가 걸려도 나머지 규칙을 계속 실행하는 전량검사 방식입니다. 자세한 내용은 [src/graph/README.md](src/graph/README.md)를 참고해 주세요. (규칙⑤를 코사인 유사도가 아닌 LLM 판정으로 설계한 이유는 아래 [트러블슈팅](#트러블슈팅) 참고.)

### 실제 작동 예시

**①PII 마스킹** — 답변에 계좌번호가 우연히 섞여도 자동으로 마스킹됩니다.

```
수정 전: 계좌번호 110-234-567890로 예금 가능합니다.
수정 후: 계좌번호 11**********로 예금 가능합니다.
```

**②필수고지 자동삽입** — 상품 추천 답변 끝에는 아래 고지문구가 항상 따라붙습니다(누락되면 이 규칙이 채워넣습니다).

```
질문: 정기예금 좋은 상품 추천해줘
답변: (상품 목록 안내) ...
※ 실제 가입 조건과 금리는 상품설명서·약관 확인 후 최종 확정됩니다. 자세한 사항은 영업점 또는 고객센터에 문의하세요.
```

**③금지표현 차단** — "제일", "가장" 같은 최상급 표현을 유도하는 질문에도 단정적 표현 없이 사실(수치)만 안전하게 답합니다.

```
질문: 제일 좋은 예금 상품 하나만 추천해줘
답변: 12개월 기준 기본 금리는 연 3.65%이고, 우대금리까지 포함하면 최대 연 3.85%의 이자를 받을 수 있습니다.
```

**④숫자 자체검증** — 답변 속 숫자가 원본 데이터와 다르면 실제 값으로 바로잡습니다.

```
수정 전: 국민은행 정기예금A 금리는 3.9%이고, 우리은행 정기예금B 금리는 3.9%입니다.
수정 후: 국민은행 정기예금A 금리는 3.8%이고, 우리은행 정기예금B 금리는 3.9%입니다.
```

**⑤citation grounding** — 답변 속 인용 주장이 실제 검색 문서로 뒷받침되는지 대조합니다. 근거가 있으면 문서 원문을 그대로 인용해 답합니다.

```
질문: 전화로 개인정보 수집 동의를 받아도 되나요?
답변: 네, 전화 통화를 통해 개인정보 수집에 대한 동의를 받는 것은 관련 법령상 허용됩니다.

문서에서는 다음과 같이 명시하고 있습니다:
"개인정보처리자는 전화상으로 개인정보 수집에 대한 정보주체의 동의를 받을 수 있다. 다만 향후 입증책임 문제가 발생할 수 있으므로 정보주체가 개인정보 수집·이용에 동의한다는 통화내용을 녹취할 수 있다."
```

## 예외처리

| Tier | 대상 | 판단 | 처리 |
| --- | --- | --- | --- |
| Tier0 | 라우팅 | 1차 분류가 범위외로 나옴 | history 참고해 재작성 후 1회 재분류, 실패하면 정직하게 범위외로 확정 |
| Tier1 | API 레벨 | 호출 자체가 실패(fail) 또는 지연(delay) | fail은 같은 조건으로 최대 1회 재시도, delay는 재시도 없이 즉시 포기 |
| Tier2 | 해석 레벨 | API는 정상인데 결과 없음 / 파라미터 무효 / tool 미선택 | LLM이 파라미터를 다시 해석해 최대 1회 재시도, 실패하면 가드레일을 생략하고 실패 사유를 반영한 정직한 안내문을 생성 |

### 실제 작동 예시

**Tier0(라우팅 재작성)** — "왜 그래요?"처럼 극단적으로 생략된 후속질문은 1차 분류가 실패하기 쉽습니다. history를 참고해 재작성한 뒤 재분류하면 복구됩니다.

```
이전 대화: "금융상품 설명의무는 뭘 설명해야 하나요?" → "일반금융소비자에게 중요사항을 이해할 수 있도록 설명해야 합니다."
질문: 왜 그래요?
답변: 금융상품 설명의무에서 일반금융소비자에게 중요사항을 설명해야 하는 법적 근거는 금융소비자보호법 제19조(설명의무) 제1항입니다.
정보열위에 있는 소비자가 거래결과에 스스로 책임질 수 있도록 필요한 정보를 제공하는 데 그 취지가 있습니다.
```

**Tier1(API fail 재시도)** — 강제로 1회 실패시킨 뒤에도, 같은 조건으로 재시도해 정상 결과를 반환합니다.

```
질문: 정기예금 좋은 상품 추천해줘 (1차 호출 강제 실패 → 재시도)
답변: 현재 가입할 수 있는 정기예금 상품 중에서 추천드릴 만한 상품은 다음과 같습니다.
1. 한국스탠다드차타드은행의 'e-그린세이브예금' — 12개월, 기본금리 연 3.65%, 우대금리 적용 시 연 3.85%
2. 전북은행의 'JB 123 정기예금(만기일시지급식)' — 12개월, 기본금리 연 3.21%, 우대금리 적용 시 연 3.81%
```

**Tier2(파라미터 재해석)** — "신한은행 18개월 정기예금"은 API에 없는 조건이라 1차 조회가 빈 결과로 돌아옵니다. LLM이 조건을 12개월로 재해석해 재조회하고, 원래 조건이 무엇이었는지 숨기지 않고 답변에 그대로 밝힙니다.

```
질문: 신한은행 18개월 정기예금 추천해줘
답변: 현재 조회 결과에 따르면 신한은행의 18개월 정기예금 상품 정보는 확인되지 않습니다. 대신, 신한은행에서 12개월(1년) 정기예금 상품으로는 '신한My플러스 정기예금'(최고 연 3.2%)과 '쏠편한 정기예금'(최고 연 3.2%)이 있습니다. 18개월 상품이 필요하시다면 신한은행에 직접 문의해 보시거나, 추가 정보를 확인해 보시는 것이 좋겠습니다.
```

## 트러블슈팅

### 가드레일 규칙⑤(citation grounding) — 코사인 유사도에서 LLM 판정으로 전환

초기엔 답변의 인용 주장과 검색된 문서의 임베딩 코사인 유사도로 근거를 검증했습니다. 그런데 위조 답변(조작된 조항번호·바꿔치기한 숫자 등)의 유사도가 정상 답변의 유사도 범위와 겹쳐, threshold 하나로는 구분이 안 됐습니다.

- **코사인 유사도**: 정상 range [0.629, 0.961](평균 0.777) / 위조 range [0.415, 0.893](평균 0.668) — 위조 50건 중 **34건(68%)**이 정상 range에 그대로 묻힘
- **LLM entailment 판정 전환 후**: 정상 50/50 오탐 없음, 위조 **46/50(92%)** 탐지

숫자·조항번호·결론 방향까지 문서와 대조해 판정할 수 있는 LLM 방식으로 바꿔 해결했습니다. 재현 실험 방법과 데이터는 [scripts/README.md](scripts/README.md)를 참고해 주세요.

### tool 선택 프롬프트 전략 — 일반 지시에서 목적 재정의 지시로 전환

후속발화가 tool이 직접 답할 내용처럼 보이지 않으면(예: "어떻게 신청하나요?") LLM이 tool 호출 자체를 거부했습니다(no_selection). 이때 이전 대화(history)는 이미 프롬프트에 포함돼 있었지만, 재시도 지시가 "이전 대화를 참고해 반드시 호출하세요" 같은 일반적인 문구였을 때는 재시도에도 계속 거부되는 경우가 있었습니다.

tool 호출의 목적을 "질문에 직접 답하는 것"이 아니라 "이전 대화 맥락의 상품 정보를 다시 확보하는 것"으로 재정의하는 구체적인 지시로 바꿔 해결했습니다.

- 5개 상품 × 모호 발화 4유형(절차형/재확인형/이유질문형/맞장구형)으로 150건을 구성했고, 그중 실제로 재시도 상황까지 간 63건을 기준으로 측정했습니다.
- **일반 지시**: tool 호출 성공 50.8%(32/63), 답변 정확도 50.8%(32/63)
- **목적 재정의 지시(현재)**: tool 호출 성공 **98.4%(62/63)**, 답변 정확도 **93.7%(59/63)**

150건 중 87건(58%)은 1차 시도에서 이미 정상적으로 풀렸습니다 — 모호해 보이는 후속질문이라고 해서 전부 어려운 것은 아니었고, 절차·방법을 묻는 유형(절차형)에서만 이 문제가 실제로 발생했습니다. 재현 방법과 데이터는 [scripts/README.md](scripts/README.md)를 참고해 주세요.

## Agent 평가 

기능별 최소 1건씩 확인하는 1차 평가셋([agent_eval_v1.json](data/eval/agent_eval_v1.json), 53건)은 각 기능이 개별적으로 정상 동작하는지만 최소 확인했습니다. 100%였지만, 단일 기능만 따로 확인하는 방식으로는 이력·예외분기가 겹치는 실제 상담 흐름의 문제를 못 잡는다고 판단해 다음 단계로 확장했습니다.

2차 복합 시나리오 평가셋([agent_quality_train.json](data/eval/agent_quality_train.json) / [agent_quality_test.json](data/eval/agent_quality_test.json))은 이력·Tier1/Tier2 예외분기·가드레일 규칙이 동시에 겹치는 케이스를 다룹니다. route·tool·가드레일 결과를 미리 예측해 expected로 못박은 뒤 실제 실행 결과와 대조하는 방식입니다.

- train 64건: 1차 실행 87.5%(56/64) → 실패 8건을 원인별로 분리
  - **agent 로직 문제(2건, 원인 1개)**: 이력 기반 tool 재사용 프롬프트가 "동일한 tool을 호출하세요"라고 써서, 사용자가 명시적으로 다른 상품을 요청해도 이전 tool을 고수함(상품전환 무시) → tool 선택 기준(발화가 새 상품을 명시하면 전환)과 조건 이어받기 기준(은행명 등은 이력에서 유지)을 분리한 프롬프트로 수정
  - **테스트셋 설계 문제(6건)**: 실제 API에 존재하지 않는 은행-상품 조합을 써서 생긴 오탐(1건), grep만으로 RAG 커버리지를 판단해 실제 코퍼스에 있는 내용을 "없다"고 오판한 라벨 오류(4건), 채점 문구 목록이 좁아 정상 응답을 fail 처리한 케이스(1건) — `retrieve()` 직접 호출·실 API 호출·전체 파이프라인 재실행으로 근본원인을 검증한 뒤 데이터만 정정(agent 코드는 안 건드림)
  - 수정 반영 후 재실행 **100%(64/64)**
- 개발에 안 쓴 별도 검증용 test 16건: **93.8%(15/16)**

단순 최종 수치가 아니라, 실패를 원인별(진짜버그 vs 테스트설계오류)로 정직하게 갈라서 각각 고치고 그 수정이 개발에 안 쓴 문항에도 통하는지 재검증한 과정이 핵심입니다. RAG 검색 자체는 별도로 결정론적 지표(Recall/Precision/MRR)와 RAGAS 4종을 측정합니다. 전체 지표와 실험과정은 [scripts/README.md](scripts/README.md)를 참고해 주세요.

### 한계

- **tool 스코프 협소**: 실제 은행 상담직원 업무에는 여신상담(신용평가·심사)처럼 이 프로젝트가 다루지 않는 업무가 더 있습니다. tool이 상품추천(5종)·환율조회로 한정돼 있어, 위 평가셋도 이 범위 안에서만 구성됐고 실제 업무 전반을 대표하지는 못합니다.
- **테스트셋이 실사용 발화 기반이 아님**: 실제 서비스였다면 축적된 사용자 발화(특히 edge 케이스)로 테스트셋을 구성할 수 있었겠지만, 이 프로젝트는 실사용 데이터가 없어 직접 설계한 케이스로만 구성했습니다. 실제 발화 분포와 얼마나 가까운지는 검증할 방법이 없습니다.
- **장문 대화이력 관리 미구현**: 대화이력이 길어질수록 프롬프트에 실리는 컨텍스트도 함께 길어지는데, 이를 요약하거나 캐싱하는 관리 로직은 없습니다. 위 평가셋의 멀티턴 케이스도 턴 수가 적어 이 문제가 실측에서 드러나지 않았습니다.
- **표본 크기의 한계**: test셋이 16건으로 작아 통계적 유의성이 제한적입니다(1건만 틀려도 결과가 6%p 이상 흔들립니다). citation grounding 평가(`citation_grounding_pool100.json`)도 별도 held-out 분리 없이 같은 데이터로 튜닝과 측정을 함께 했습니다 — 위 수치들은 확정값보다는 방향성 참고용으로 해석하는 게 안전합니다.

## 실행 가이드

```bash
git clone <repo-url>
cd financial-agent-copilot
pip install -e .

cp .env.example .env
# .env에 OPENAI_API_KEY / FINLIFE_API_KEY / ECOS_API_KEY 입력

python src/cli.py
```

RAG 인덱스는 `data/rag/`에 이미 빌드돼 포함돼있어 별도 빌드 없이 바로 실행 가능합니다.

테스트 실행:

```bash
pip install -e ".[dev]"
PYTHONPATH=src pytest
```
